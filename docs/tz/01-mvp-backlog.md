# MVP-бэклог

## Этап 0: проектирование

- Зафиксировать продуктовые решения, которые берем из Shopify, self-hosted платформ, headless commerce, Forest Admin/Retool и Medusa/Saleor.
- Зафиксировать инженерные принципы MVP: понятные задачи, дисциплина документации, аккуратное ведение модулей и проверяемый результат.
- Зафиксировать режимы размещения: Managed Store и Own Infra.
- Разложить Own Infra на варианты: фронт у клиента, БД у клиента, full client infra через agent/API.
- Описать сценарий demo/pilot на поддомене ShopsBox и production-перенос на выбранный хостинг.
- Зафиксировать выбранную multi-tenant стратегию для MVP: shared app + shared DB + tenant_id/store_id.
- Проанализировать схемы/модели аналогов и обновить нашу модель БД.
- Описать доменную модель каталога, заказов и клиентов.
- Описать основные API endpoints.
- Описать роли и права.
- Описать схему деплоя Docker Compose.
- Описать границы ответственности по нагрузке, поддержке и managed hosting.
- Описать учет ресурсов по клиентам: диск, API/БД-нагрузка, статика/CDN, бэкапы, логи и лимиты тарифов.
- Описать правила увеличения лимитов: что входит в тариф, что продается add-on, что требует перехода на старший или dedicated-тариф.
- Описать инфраструктурную модель: shared managed-контур, поддомены, общая админка, dedicated-контуры и Kubernetes как будущий этап.
- Разбить работу на GitHub issues.
- Создать milestones и labels.
- Подготовить GitHub Project board.
- Подготовить текстовые прототипы ключевых страниц вместо Figma.
- Зафиксировать бизнес-модель и предварительные тарифные направления.
- Зафиксировать стратегию настройки витрины: settings, blocks, templates, custom CSS позже.

- Настроить миграции.

## Не делать в первом MVP

- Kubernetes.
- Полную desktop-админку.
- Полный клиентский mobile app для покупателей.
- Сложный конструктор тем.
- Marketplace расширений.
- Много платежных и складских интеграций одновременно.
- Figma-макеты как обязательный этап.
- Отдельную внешнюю доску задач.

## Дальний backlog

- Исследовать интеграцию интернет-магазинов с 1С как отдельное стратегическое направление. Цель - заранее понять реальные боли обмена заказами, товарами, остатками, ценами и статусами, чтобы ShopsBox мог предложить более надежный сценарий, чем типовые слабые интеграции у конкурентов.
- Для исследования 1С подготовить отдельную локальную лабораторию: развернуть тестовый контур 1С, изучить варианты обмена, форматы, ограничения, типовые ошибки синхронизации и требования клиентов.
- После исследования описать архитектуру интеграционного модуля 1С: границы ответственности, очереди/повторы, журнал обмена, ручное восстановление, лимиты нагрузки, безопасность и влияние на тарифы.
- Спроектировать монетизацию бесплатных тарифов через Яндекс Рекламу: использовать существующий рекламный слот в админке клиента, добавить безопасные рекламные слоты на витрине и описать правила отключения рекламы в платных тарифах.
