# Auth code delivery: SMS/email и dev-заглушки

Документ фиксирует отдельную задачу для входа по одноразовому коду. Это не часть текущего Docker/Symfony foundation, но ее нужно учесть до полноценной реализации пользователей и ролей.

## Цель

Сделать безопасную основу авторизации по одноразовому коду:

- пользователь запрашивает код входа по телефону или email;
- backend создает код с ограниченным сроком жизни;
- после истечения срока код нельзя использовать для входа;
- в dev-режиме SMS/email не отправляются наружу, а имитируются локальной заглушкой;
- dev SMS-код можно показать во flash-сообщении, как в CorporateHouse, чтобы быстро проверять сценарий руками.

## MVP-сценарии

1. Пользователь вводит телефон или email.
2. Backend создает одноразовый код, срок действия и запись попытки входа.
3. Application-слой вызывает интерфейс доставки кода.
4. В dev-режиме infrastructure-адаптер не отправляет SMS/email наружу, а возвращает данные для flash-сообщения.
5. Пользователь вводит код.
6. Backend проверяет, что код существует, относится к этому получателю, не использован, не истек и не превышен лимит попыток.
7. После успешной проверки код помечается использованным.

## Важные правила безопасности

- Истекший код всегда отклоняется, даже если значение кода верное.
- Повторно использованный код отклоняется.
- Код хранить не в открытом виде, а как hash.
- Ограничить число попыток ввода для одной заявки.
- Dev flash-сообщение с кодом разрешено только в локальном/dev окружении.
- В production нельзя выводить код во flash, HTML, API response или обычные пользовательские логи.
- SMS/email provider подключать через infrastructure-адаптеры, не из controller.

## Предварительные endpoints

- `POST /api/auth/code/request` - запросить одноразовый код.
- `POST /api/auth/code/verify` - проверить код и создать сессию/токен.

Точные URL можно уточнить при реализации auth-модуля, но сценарий должен оставаться API-first, чтобы web, mobile и desktop клиенты использовали один backend.

## Слои

- `Application` - use cases `RequestLoginCode` и `VerifyLoginCode`.
- `Domain` - правила срока жизни, статуса кода, попыток и одноразового использования.
- `Infrastructure` - Doctrine persistence, SMS/email delivery adapters, dev fake delivery.
- `Presentation` - HTTP controllers и flash-сообщение для dev web-сценария.

## Не делать в первой версии

- Не подключать реального SMS-провайдера до отдельного решения по тарифам и стоимости отправки.
- Не делать сложную enterprise MFA-модель.
- Не смешивать dev-заглушку с production-настройками.
- Не использовать SMS как единственный вечный способ доступа без email/recovery-сценария.
