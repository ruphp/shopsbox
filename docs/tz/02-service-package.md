# Пакет подготовки ТЗ для ShopsBox

Этот документ фиксирует, как мы применяем собственную услугу "ТЗ и архитектура" к проекту ShopsBox.

## Выбранный уровень

Берем уровень "Максимум", но адаптируем его под свой процесс:

- без Figma;
- без отдельной внешней доски задач;
- процесс разработки через GitHub;
- документация в Markdown внутри репозитория;
- схемы через Mermaid;
- прототипы пока в текстовом виде, позже возможны HTML-прототипы.

## Что должно получиться

- Описание продукта и позиционирования.
- Список ролей.
- Список страниц и модулей.
- Детальное описание страниц: логика, сценарии, состояния.
- User Stories.
- Функциональные требования.
- Бизнес-правила.
- Список сущностей БД: таблицы и поля.
- ER-диаграмма Mermaid.
- Описание API endpoints.
- Архитектура backend, frontend, mobile/desktop и инфраструктуры.
- План работ со сроками и приоритетами.
- GitHub: labels, milestones, issues, pull requests.

## Что не входит в первый проход

- Реальные Figma-макеты.
- отдельная внешняя доска задач.
- Kubernetes manifests.
- Полная реализация mobile/desktop приложений.
- Финальные production SLA.
- Полный финансовый план.

## Этапы выполнения

Текущий прогресс по этапам ведется в [Карте прогресса ТЗ](08-tz-progress-map.md).

### Этап 1: требования и границы

- Зафиксировать хорошие решения из похожих продуктов и определить, что берем в MVP.
- Зафиксировать бизнес-модель: Managed Store и Own Infra.
- Определить целевого клиента первого релиза.
- Определить MVP-функции.
- Зафиксировать ограничения: без Figma, без отдельной внешней доски задач, без Kubernetes на старте.

### Этап 2: структура продукта

- Описать карту страниц.
- Описать роли и права.
- Описать основные сценарии пользователя.
- Описать супер-админку платформы.

### Этап 3: техническая архитектура

- Зафиксировать Symfony backend.
- Зафиксировать Clean Architecture / DDD слои.
- Определить multi-tenant стратегию.
- Описать API-first подход.
- Описать Docker Compose контур.
- Отложить Kubernetes до будущей фазы.

### Этап 4: спецификация разработки

- Составить список сущностей БД.
- Составить API endpoints.
- Составить User Stories.
- Разбить MVP на GitHub issues.
- Определить milestones и labels.
