# Глоссарий

В документах и коде технические названия часто будут на английском, потому что так принято в Symfony, Doctrine, API и БД. Но для понимания проекта рядом держим русское объяснение.

Правило: в объяснениях сначала русский термин, потом английский в скобках.

## Базовые сущности платформы

### Клиент платформы (Tenant)

Компания или человек, который покупает наш сервис. У одного клиента платформы может быть один или несколько магазинов.

Пример: ИП Иванов купил у нас интернет-магазин. ИП Иванов - это клиент платформы.

### Магазин (Store)

Конкретный интернет-магазин внутри платформы. У магазина есть название, домен, валюта, настройки, товары, заказы и покупатели.

Пример: `ivanov-shop.ru` - это магазин.

### Пользователь админки (User)

Человек, который входит в админку: владелец магазина, менеджер, оператор платформы.

### Роль (Role)

Набор прав пользователя.

Пример: владелец, менеджер заказов, контент-менеджер, оператор платформы.

### Роль пользователя (UserRole)

Связь пользователя с ролью. Нужна, чтобы один человек мог иметь разные права в разных магазинах.

## Каналы продаж

### Канал продаж (SalesChannel)

Место или способ, через который магазин продает товары.

Примеры:

- web-витрина;
- мобильное приложение;
- маркетплейс;
- отдельная витрина для оптовиков.

В MVP можно начать с одного канала: `web`.

## Каталог

### Товар (Product)

Общее описание товара: название, описание, статус, картинки, категории.

Важно: товар сам по себе не всегда является продаваемой единицей. Продается обычно вариант товара.

Пример: "Футболка Basic" - это товар.

### Вариант товара (ProductVariant)

Конкретная продаваемая версия товара с SKU, ценой и характеристиками.

Пример: "Футболка Basic, размер M, цвет черный" - это вариант товара.

Для простого товара без размеров и цветов все равно можно создать один вариант.

### Опция товара (ProductOption)

Признак, по которому товар имеет варианты.

Пример: размер, цвет, объем, материал.

### Значение опции товара (ProductOptionValue)

Конкретное значение опции.

Пример: для опции "размер" значения будут `S`, `M`, `L`. Для опции "цвет" - `черный`, `белый`, `красный`.

### Значение опции у варианта (VariantOptionValue)

Связь варианта товара с выбранными значениями опций.

Пример: вариант "Футболка Basic M черная" связан со значениями "размер M" и "цвет черный".

### Категория (Category)

Раздел каталога.

Пример: "Одежда", "Обувь", "Аксессуары".

### Категория товара (ProductCategory)

Связь товара с категорией. Нужна, чтобы товар мог быть в одной или нескольких категориях.

### Изображение товара (ProductImage)

Фото товара или конкретного варианта товара.

## Склад

### Складская единица (InventoryItem)

То, что учитывается на складе. Обычно связано с вариантом товара.

Пример: вариант "Футболка Basic M черная" имеет складскую единицу с тем же SKU.

### Склад / точка хранения (StockLocation)

Место, где физически лежит товар.

Пример: основной склад, магазин на улице Ленина, пункт выдачи.

### Остаток на складе (InventoryLevel)

Количество конкретной складской единицы на конкретном складе.

Пример: "Футболка Basic M черная" - 15 штук на основном складе.

### Резерв товара (InventoryReservation)

Количество товара, которое временно зарезервировано под корзину или заказ.

Пример: покупатель оформляет заказ на 2 футболки. Эти 2 штуки резервируются, чтобы их не продали повторно.

## Покупатели

### Покупатель (Customer)

Клиент магазина, который покупает товары.

### Адрес покупателя (CustomerAddress)

Адрес покупателя для доставки или профиля.

## Корзина и заказы

### Корзина (Cart)

Набор товаров, которые покупатель собирается купить, но еще не оформил как заказ.

### Позиция корзины (CartItem)

Одна строка в корзине: какой вариант товара, сколько штук и по какой цене.

### Заказ (Order)

Оформленная покупка. В заказе фиксируются покупатель, сумма, статус, товары, доставка и оплата.

### Позиция заказа (OrderItem)

Одна строка в заказе: какой товар купили, сколько штук и по какой цене.

Важно: в заказе нужно хранить название и цену на момент покупки, даже если потом товар переименовали или цена изменилась.

### Адрес заказа (OrderAddress)

Адрес доставки или платежный адрес, сохраненный внутри заказа.

### История статусов заказа (OrderStatusHistory)

Журнал изменений статуса заказа.

Пример: `new -> paid -> shipped -> completed`.

## Оплата и доставка

### Платеж (Payment)

Информация об оплате заказа: провайдер, статус, сумма, внешний ID платежа.

### Доставка (Delivery)

Информация о доставке заказа: способ доставки, статус, адрес, трек-номер.

## Операционная часть

### Файл (File)

Запись о загруженном файле: картинка товара, документ, импорт.

### Журнал действий (AuditLog)

Запись о важном действии в админке.

Пример: пользователь изменил цену товара или сменил статус заказа.

### Бэкап (Backup)

Запись о резервной копии магазина или данных.

## Symfony и база данных

### Миграции Doctrine (Doctrine Migrations)

Файлы, которые описывают изменения структуры базы данных.

Пример: создать таблицу товаров, добавить поле цены, добавить индекс для поиска.

Важно: миграции не работают на каждом запросе пользователя. Они запускаются при обновлении проекта или изменении схемы БД.

### ORM Doctrine (Doctrine ORM)

Инструмент, который помогает работать с таблицами БД через PHP-объекты.

Пример: загрузить товар как объект `Product`, изменить название, сохранить.

ORM удобна для обычной админки и понятных сценариев, но не всегда подходит для тяжелых массовых операций.

### DBAL Doctrine (Doctrine DBAL)

Более низкоуровневый способ работать с БД через SQL и query builder.

DBAL полезен для быстрых и сложных запросов: отчеты, массовые обновления, складские пересчеты, импорты.

### Горячий запрос (Hot Path)

Участок системы, который выполняется очень часто или сильно влияет на скорость.

Пример: резервирование остатков при оформлении заказа.

Для таких мест можно использовать DBAL/native SQL вместо ORM.
