# План следующих задач

Документ фиксирует рабочий черновик следующих issues после завершения foundation-этапа `01 Основа MVP`.

## Текущая логика очереди

После `#5 Основа учета ресурсов и лимитов` foundation-этап можно считать закрытым: есть backend skeleton, tenant foundation, file storage foundation, локальные операции и основа учета ресурсов.

Следующий этап должен перейти от технического фундамента к первому бизнес-модулю.

## Предлагаемые следующие issues

### #6 Catalog foundation

Цель: создать минимальный модуль `Catalog` для товаров и категорий.

Границы:

- создать структуру `backend/src/Catalog`;
- добавить таблицы `products` и `categories`;
- учесть `tenant_id` и `store_id`;
- добавить базовые статусы товара: draft/active/archived;
- не делать изображения товара в этой же задаче;
- не делать остатки, скидки, варианты и SEO раньше времени.

Проверки:

- миграция применяется;
- Doctrine mapping проходит;
- если появятся правила статусов товара, добавить unit-тесты.

### #7 Product image upload

Цель: впервые использовать `FileStorage` в реальном сценарии.

Границы:

- добавить сценарий загрузки изображения товара;
- сохранить файл через `FileStorage`;
- связать файл с product;
- определить минимальные metadata: key, public_url, mime type, size, product_id;
- проверить повторяемость local storage URL.

Проверки:

- unit-тест use case;
- integration/functional проверка загрузки через HTTP;
- проверка, что файл не хранится внутри контейнера приложения.

### #8 Storefront skeleton

Цель: показать первые публичные страницы магазина без checkout.

Границы:

- главная витрины;
- список товаров;
- карточка товара;
- определение store по домену или временно по route/slug;
- без корзины и заказов.

Проверки:

- functional tests на доступность страниц;
- проверка tenant/store boundary.

### #9 Admin catalog CRUD

Цель: дать владельцу магазина минимальное управление товарами.

Границы:

- список товаров;
- создание товара;
- редактирование товара;
- публикация/скрытие;
- без сложного UI и без drag-and-drop изображений.

Проверки:

- use case unit tests для правил;
- functional tests на основные HTTP-сценарии.

## Что не создавать отдельным issue прямо сейчас

- Полный billing engine.
- Полный order/checkout до появления каталога.
- CDN-интеграцию до реального трафика.
- Kubernetes/deploy automation.
- Сложный theme builder.

## Рекомендуемый следующий шаг

После закрытия `#5` создать `#6 Catalog foundation`.

Это даст первый настоящий бизнес-модуль и начнет связывать уже готовые foundation-слои: tenant boundary, migrations, file storage позже, resource usage позже.
