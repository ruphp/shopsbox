# Публикация магазина на поддомене ShopsBox

Issue #45 фиксирует, что публичный поддомен магазина не включается автоматически при создании магазина.

## Два типа доступа

У магазина должны быть разные адреса:

- технический preview URL;
- публичный поддомен.

Preview URL нужен владельцу, сотрудникам магазина, модераторам и администраторам. Покупатели не должны видеть приватный preview без авторизации.

Публичный поддомен вида `{store}.shopsbox.ru` включается только после осознанной публикации.

## Модель

В модели магазина нужны поля:

- `preview_token` или отдельный технический route identifier;
- `public_subdomain`;
- `publication_status`;
- `publication_requested_at`;
- `published_at`;
- `blocked_at`;
- `block_reason` nullable.

`slug` магазина не равен публичному поддомену. Slug может быть внутренним стабильным идентификатором, а поддомен должен проходить отдельную проверку.

## Статусы публикации

Минимальные статусы:

- `draft` - магазин создан, публичный поддомен выключен;
- `pending_review` - владелец запросил публикацию;
- `published` - магазин доступен на публичном поддомене;
- `blocked` - публичный доступ отключен из-за нарушения или ручного решения.

Технический preview может быть доступен владельцу даже в `draft`, но публичная витрина для покупателей должна открываться только в `published`.

## Правила поддомена

Поддомен должен:

- быть в нижнем регистре;
- содержать только латинские буквы, цифры и дефис;
- начинаться и заканчиваться буквой или цифрой;
- иметь длину от 3 до 40 символов;
- быть уникальным;
- не входить в список системных имен.

Запрещенные системные имена:

- `www`;
- `api`;
- `admin`;
- `app`;
- `static`;
- `assets`;
- `cdn`;
- `mail`;
- `smtp`;
- `ftp`;
- `support`;
- `help`;
- `billing`;
- `status`;
- `demo`;
- `shopsbox`.

## Перед публикацией

Перед включением поддомена нужно проверить:

- магазин принадлежит текущему владельцу;
- публичный поддомен валиден и свободен;
- юридическое подтверждение актуальной версии принято;
- магазин не заблокирован;
- есть минимальные данные магазина;
- есть хотя бы один активный товар или разрешен пустой preview-пуск;
- DNS/HTTPS wildcard настроены на стороне платформы.

## Sitemap и навигация

Технический preview URL нельзя добавлять:

- в sitemap;
- в публичную навигацию;
- в canonical URL;
- в Open Graph URL.

Публичные SEO-ссылки должны строиться только для `published` магазина.

## Доступ

Preview:

- владелец магазина;
- сотрудники магазина;
- модератор;
- администратор платформы.

Публичный поддомен:

- все посетители, если `publication_status = published`;
- 404 или заглушка, если магазин не опубликован;
- 403/410 или отдельная страница блокировки, если магазин заблокирован.

## Проверки и тестовое покрытие

На этапе проектирования тесты не нужны.

При реализации нужны:

- unit-тесты валидатора поддомена;
- unit-тесты запрещенных системных имен;
- integration-тест уникальности поддомена;
- functional-тест: draft магазин не открывается публично;
- functional-тест: preview доступен владельцу;
- functional-тест: published магазин открывается на поддомене.
