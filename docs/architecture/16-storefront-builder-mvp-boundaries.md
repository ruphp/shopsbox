# Конструктор витрины: зависимости и границы MVP

Issue #84 фиксирует, что builder не должен стартовать как отдельная игрушка без базовой управляемой витрины.

## Что должно быть готово до builder

- Регистрация владельца и первый магазин.
- Кабинет владельца с понятной навигацией.
- Настройки магазина: контакты, юридические данные, доставка и оплата.
- Каталог: товары, категории, изображения, статусы публикации.
- Медиатека и лимиты файлов.
- Публичная витрина магазина.
- Базовая корзина и checkout.
- Fake-оплата для MVP, до подключения реального эквайринга.

## Какие сущности использует builder

- `Store`: владелец, статус, настройки, домен, публикация.
- `Product`: карточки, статусы, изображения, категории.
- `Category`: навигация и подборки.
- `StoreMediaFile`: изображения и файлы для блоков.
- `StorefrontPage`: будущая страница витрины.
- `Checkout`: будущие блоки корзины, доставки и оплаты.

## MVP-модель builder

Ориентир по мышлению: YOOtheme, но первый ShopsBox MVP проще:

- страница;
- раздел;
- ряд;
- колонка;
- блок.

Свободные блоки:

- текст;
- изображение;
- кнопка;
- баннер;
- HTML не разрешен на MVP;
- произвольный CSS не разрешен на MVP.

Системные блоки:

- список товаров;
- карточка товара;
- категории;
- корзина;
- контакты магазина;
- доставка и оплата;
- юридическая информация продавца.

## Разные типы страниц

Для разных типов страниц нужен разный реестр доступных блоков:

- главная: hero, подборки, категории, баннеры, контакты;
- категория: список товаров, фильтры позже, описание категории;
- товар: карточка товара, изображения, характеристики, варианты позже;
- корзина: состав заказа, доставка, оплата;
- служебные страницы: контакты, доставка, оплата, политика магазина.

## Что не делать в MVP

- произвольный HTML/CSS;
- drag-and-drop любой вложенности;
- сложные анимации;
- marketplace шаблонов;
- пользовательские JS-скрипты;
- визуальный редактор пиксель-в-пиксель;
- сложные адаптивные правила на каждый breakpoint.

## Порядок реализации

1. Закрыть регистрацию, кабинет и настройки магазина.
2. Довести управляемую витрину до базового состояния.
3. Добавить модель страниц, секций, рядов, колонок и блоков.
4. Добавить реестр блоков по типам страниц.
5. Подключить первые системные блоки к существующим товарам, категориям и настройкам магазина.
6. Только после этого развивать визуальное редактирование.
