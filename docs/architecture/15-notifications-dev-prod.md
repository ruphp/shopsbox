# Уведомления: dev и production

Issue #65 фиксирует правила уведомлений для регистрации, публикации и модерации.

## Dev-режим

- Телефонные коды доставляются через `flash_dev`.
- Код показывается во временном flash-сообщении и пишется в `backend/var/auth-codes.log`.
- Email-уведомления на локалке идут через тестовый mailer или лог, без реальной отправки.
- Dev-режим нужен для проверки сценариев без расходов и внешних SMS/SMTP-зависимостей.

## Production-режим

- Email должен уходить через реальный SMTP или транзакционный email-провайдер.
- SMS должен уходить через отдельного SMS-провайдера.
- Секреты провайдеров нельзя хранить в git. Они должны жить в `.env.local`, переменных окружения сервера или секрет-хранилище.

## Контракты

- Код сценариев не должен напрямую знать про flash, SMTP или конкретный SMS API.
- Application вызывает контракт доставки.
- Infrastructure реализует контракт:
  - dev: flash/log;
  - prod: SMTP/SMS adapter.
- Текущий контракт одноразовых кодов: `Tenant/Application/Contracts/AuthCodeDelivery`.

## Env-настройки

Безопасные ключи зафиксированы в `.env.example` и локальном `.env` без реальных секретов:

- `NOTIFICATION_MODE`;
- `MAILER_DSN`;
- `NOTIFICATION_EMAIL_FROM`;
- `SMS_PROVIDER`;
- `SMS_API_BASE_URL`;
- `SMS_API_KEY`;
- `SMS_SENDER`.

Для production значения должны быть переопределены на сервере. `SMS_API_KEY` и реальные пароли SMTP в git не коммитятся.

## Лимиты

- Повторный код на тот же email или телефон не выпускается, пока активный код не подтвержден.
- На один канал и получателя действует ограничение частоты запросов.
- Количество попыток ввода кода ограничено в сущности `AuthCode`.
- Для production SMS нужно дополнительно учитывать дневные лимиты провайдера и антифрод по IP.

## Чеклист перед production

1. Выбрать SMTP-провайдера и прописать `MAILER_DSN` на сервере.
2. Выбрать SMS-провайдера и прописать `SMS_PROVIDER`, `SMS_API_BASE_URL`, `SMS_API_KEY`, `SMS_SENDER`.
3. Реализовать production adapter для SMS.
4. Реализовать production adapter для email-уведомлений.
5. Проверить лимиты: повторные запросы, неверные коды, блокировка частых попыток.
6. Проверить журналы доставки и ошибок без вывода секретов.

## Проверки и тестовое покрытие

Новые тесты не добавлены по текущей договоренности.

Проверки:

- `php -l` адаптера dev-доставки;
- `lint:container`;
- smoke-check `/auth/code`.
