# Подтверждение телефона при первой работе

Issue #64 усиливает dev-подтверждение телефона из #62 и добавляет первый обязательный контур.

## Что сделано

- Создание магазина через `POST /tenants` требует подтвержденный телефон в сессии.
- Страница публикации магазина `/owner/store/publication` требует подтвержденный телефон и отправляет владельца на `/auth/code?phone_required=1`.
- В форме входа по коду при таком переходе сразу выбран канал `phone`.
- В сущность пользователя добавлены поля для будущей привязки подтвержденного телефона:
  - `verified_phone`;
  - `phone_verified_at`;
  - `phone_verified_ip`;
  - `phone_verified_user_agent`;
  - `phone_verification_provider`.

## Ограничения MVP

Сценария полноценной регистрации пользователя пока нет, поэтому связь `user_id -> phone` подготовлена на уровне модели и миграции, но сам use case привязки будет корректно доделывать после появления регистрации. Сейчас фактическая проверка доступа работает через подтвержденный телефон в сессии.

## Проверки и тестовое покрытие

Новые тесты не добавлены по текущей договоренности.

Проверки:

- миграция;
- `php -l` измененных PHP-файлов;
- `lint:container`;
- `doctrine:schema:validate --skip-sync`;
- smoke-check `/auth/code?phone_required=1`;
- smoke-check запрета `POST /tenants` без подтвержденного телефона.
