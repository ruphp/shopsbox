# Локальная разработка

Основной локальный runtime - Docker Compose. Backend получает обязательные dev-переменные из `compose.yaml`, а `backend/.env` хранит только безопасные Symfony-defaults без production-секретов. Реальные `backend/.env.dev`, `backend/.env.test`, `backend/.env.local` и другие machine-specific env-файлы не хранятся в git.

Для личных локальных переопределений можно создать `backend/.env` на основе `backend/.env.example`. Такой файл должен оставаться только на машине разработчика.

## Главное правило

Вся проектная работа идет через `make`.

Причина простая: PowerShell часто ломает кириллицу и многострочный текст. Поэтому PowerShell может быть только транспортом для запуска `make`, но не рабочей средой проекта.

## Менторский режим

После крупных изменений нужно дополнительно объяснять владельцу проекта:

- что изменилось;
- где это находится;
- как это проходит по слоям;
- какая часть относится к Symfony;
- какая часть относится к нашей бизнес-логике;
- как это можно объяснить на собеседовании;
- какие компромиссы приняты и что можно переделать позже.

Это особенно важно, потому что Symfony для владельца проекта новый стек.

## Как добавлять команды

- Если операция повторяется, добавить ее в `Makefile`.
- Если операция требует PHP, Composer, Symfony, PostgreSQL, Redis, очередей или сборки клиентов, выполнять ее внутри Docker/проектного контура.
- Если операция работает с GitHub CLI и русским текстом, передавать текст через UTF-8 файл.
- Если для разработки нужен отдельный сервис, добавить Docker Compose конфигурацию и `make`-цель.

## Стартовые команды

Пока код приложения не создан, `Makefile` содержит только каркас. По мере появления backend, frontend и mobile-модулей в него нужно добавлять реальные команды:

- `make help`
- `make docs-list`
- `make docs-check`
- `make up`
- `make down`
- `make test`

## Будущая структура команд

- `make up` - поднять локальный Docker Compose контур.
- `make down` - остановить локальный контур.
- `make logs` - показать логи сервисов.
- `make backend-shell` - открыть shell backend-контейнера.
- `make migrate` - применить миграции.
- `make test` - запустить проверки.
- `make issue-create` - создать issue через GitHub CLI с текстом из UTF-8 файла.
- `make pr-create` - создать PR через GitHub CLI с текстом из UTF-8 файла.

## Имена Docker-ресурсов

Локальные Docker Compose project, containers, networks and volumes должны использовать префикс `shopsbox_`.

Примеры:

- `shopsbox_backend`;
- `shopsbox_postgres`;
- `shopsbox_redis`;
- `shopsbox_minio`;
- `shopsbox_worker`;
- `shopsbox_scheduler`;
- `shopsbox_postgres_data`;
- `shopsbox_minio_data`.

Это нужно, чтобы ресурсы ShopsBox не смешивались с другими проектами на той же машине.
