# Авторизация по одноразовому коду

Issue #22 добавляет базовый сценарий входа владельца магазина или клиента по одноразовому коду.

## Сценарий

1. Пользователь открывает `/auth/code`.
2. Вводит email.
3. `RequestAuthCodeUseCase` создает шестизначный код.
4. Код сохраняется в таблицу `auth_codes` в виде SHA-256 hash.
5. Dev-доставка записывает код в `var/auth-codes.log`.
6. Пользователь вводит код.
7. `VerifyAuthCodeUseCase` проверяет TTL, одноразовость и лимит попыток.
8. При успехе email сохраняется в session key `shopsbox_auth_email`.

## Ограничения текущей версии

- Реального SMS/email провайдера пока нет.
- Dev-доставка нужна только для локальной разработки и закрытой мини-беты.
- Полноценная Symfony-аутентификация пользователя будет следующим шагом после согласования модели пользователей и кабинета.

## Contracts

- `AuthCodeRepository` отвечает за хранение и поиск активного кода.
- `AuthCodeDelivery` отвечает за доставку кода.

Infrastructure реализует эти contracts через Doctrine repository и dev file adapter.

## Проверки и тестовое покрытие

Новые unit-тесты в этой задаче сознательно не добавлены: по договоренности тесты на авторизацию разберем отдельно после основной мини-беты.

Что нужно покрыть позже:

- успешный request code;
- неверный email;
- успешный verify code;
- неверный код;
- просроченный код;
- повторное использование кода;
- превышение лимита попыток.
