# Настройки темы витрины

Issue #28 добавляет первый управляемый слой внешнего вида витрины без полноценного page builder.

## Что хранится

Настройки лежат в `stores.theme_settings` как JSON:

- `accent` - один из безопасных пресетов цвета: `blue`, `green`, `coral`;
- `hero_title` - заголовок hero-блока;
- `hero_text` - текст hero-блока;
- `sections` - включенные секции витрины: `hero`, `featured`, `contacts`.

Полноценный drag-and-drop, произвольные блоки и переносимые шаблоны остаются для отдельной архитектурной задачи.

## Почему JSON

На MVP набор настроек небольшой и относится к одному магазину. JSON позволяет хранить структурированные настройки темы без преждевременного набора таблиц под будущий page builder.

Когда появятся сложные секции, версии шаблонов и порядок блоков с настройками, эту модель можно вынести в отдельные таблицы или документную структуру builder-а.

## Где меняется

- владелец магазина редактирует настройки в кабинете;
- use case нормализует и валидирует значения;
- витрина читает настройки через read model магазина;
- CSS для витрины лежит в `public/assets/storefront.css`, не в Twig.

## Проверки и тестовое покрытие

Новые unit-тесты не добавлены: в задаче есть простая нормализация input, но без сложного доменного правила. При развитии темы стоит добавить unit-тесты на допустимые пресеты и секции.

Проверки:

- `doctrine:migrations:migrate --no-interaction`;
- `lint:container`;
- `doctrine:schema:validate --skip-sync`;
- `lint:twig templates/tenant templates/storefront`;
- smoke-check главной витрины;
- smoke-check редиректа кабинета без авторизации.
