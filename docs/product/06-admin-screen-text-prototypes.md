# Текстовые прототипы экранов админки

Документ описывает ключевые экраны админки владельца магазина для MVP. Это не визуальный дизайн, а продуктовый прототип: какие блоки есть на странице, какие действия выполняет пользователь, какие данные нужны backend и какие состояния нужно предусмотреть.

Основа: прототип админки на основе аналогов, модель данных и текущая карта страниц. Главный принцип: владелец магазина должен быстро понять, что происходит, и выполнить ежедневные операции без технической путаницы.

## Общая навигация MVP

Основное меню админки владельца:

```text
Сегодня
Заказы
Каталог
Склад
Клиенты
Витрина
Настройки
Техника
Поддержка
```

Маркетинг, аналитика, интеграции и биллинг можно показать как будущие разделы, но не делать центральными в первом MVP.

Глобальные элементы:

- переключатель магазина, если у пользователя больше одного магазина;
- быстрый поиск по товарам, заказам и клиентам позже;
- индикатор технических проблем: домен, SSL, бэкапы;
- профиль пользователя и выход;
- ссылка на поддержку.

## Экран 1: Сегодня

Цель: дать владельцу магазина стартовый рабочий экран на день.

Основные блоки:

- продажи: сегодня, 7 дней, 30 дней;
- новые заказы;
- заказы, требующие действия;
- товары с низким остатком;
- технические предупреждения;
- быстрые действия.

Действия:

- открыть список новых заказов;
- открыть конкретный заказ;
- добавить товар;
- перейти к остаткам;
- открыть техническое состояние;
- создать обращение в поддержку.

Данные:

- `orders`;
- `order_items`;
- `inventory_levels`;
- `products`;
- `product_variants`;
- `backups`;
- `stores`.

Состояния:

- новый магазин без заказов;
- есть новые заказы;
- есть проблема с доменом или SSL;
- нет свежего бэкапа;
- есть товары с низким остатком.

MVP:

- простые числовые показатели;
- списки задач без сложной аналитики;
- быстрые ссылки на нужные разделы.

Позже:

- настраиваемые метрики;
- графики;
- подсказки;
- инсайты по продажам.

## Экран 2: Список заказов

Цель: быстро найти и обработать заказ.

Основные блоки:

- фильтры: статус, период, поиск по номеру/клиенту;
- таблица заказов;
- быстрые статусы;
- массовые действия позже.

Колонки:

- номер заказа;
- дата;
- покупатель;
- статус заказа;
- статус оплаты;
- статус доставки;
- сумма;
- канал продаж;
- последнее изменение.

Действия:

- открыть заказ;
- изменить статус позже через карточку;
- отфильтровать новые заказы;
- найти заказ по номеру;
- перейти к покупателю.

Данные:

- `orders`;
- `customers`;
- `payments`;
- `deliveries`;
- `sales_channels`.

Состояния:

- заказов нет;
- много заказов;
- фильтр ничего не нашел;
- есть заказы с ошибкой оплаты;
- есть заказы без доставки.

MVP:

- список;
- фильтр по статусу;
- поиск по номеру;
- переход в карточку заказа.

Позже:

- экспорт;
- печать;
- массовая смена статуса;
- возвраты.

## Экран 3: Карточка заказа

Цель: обработать конкретный заказ и видеть всю историю.

Основные блоки:

- шапка: номер, статус, дата, сумма;
- покупатель и контакты;
- товары заказа;
- оплата;
- доставка;
- история статусов;
- комментарий менеджера;
- журнал технических событий.

Действия:

- изменить статус заказа;
- добавить комментарий;
- открыть покупателя;
- открыть товар;
- отметить оплату вручную в MVP;
- отметить доставку вручную в MVP.

Данные:

- `orders`;
- `order_items`;
- `order_addresses`;
- `order_status_history`;
- `customers`;
- `payments`;
- `deliveries`;
- `audit_logs`.

Состояния:

- новый заказ;
- заказ ожидает оплаты;
- заказ оплачен;
- заказ передан в доставку;
- заказ отменен;
- ошибка платежа;
- нет адреса доставки для цифрового/самовывозного сценария.

MVP:

- ручная смена статуса;
- история статусов;
- комментарии;
- просмотр состава заказа.

Позже:

- возвраты;
- частичная отгрузка;
- интеграции оплат и доставок;
- печатные документы.

## Экран 4: Список товаров

Цель: управлять ассортиментом магазина.

Основные блоки:

- поиск по названию/SKU;
- фильтр по статусу;
- фильтр по категории;
- таблица товаров;
- кнопка создания товара.

Колонки:

- изображение;
- название;
- статус публикации;
- категория;
- количество вариантов;
- минимальная цена;
- остаток;
- дата обновления.

Действия:

- создать товар;
- открыть товар;
- скрыть/опубликовать товар;
- перейти к остаткам товара;
- перейти к категории.

Данные:

- `products`;
- `product_variants`;
- `product_images`;
- `product_categories`;
- `categories`;
- `inventory_items`;
- `inventory_levels`.

Состояния:

- товаров нет;
- товар без изображения;
- товар скрыт;
- товар без остатков;
- товар с несколькими вариантами;
- поиск ничего не нашел.

MVP:

- список;
- поиск;
- создание;
- редактирование;
- публикация/скрытие.

Позже:

- импорт/экспорт;
- массовое редактирование;
- расширенные фильтры;
- SEO-аудит.

## Экран 5: Карточка товара

Цель: создать или отредактировать товар без смешивания каталога и склада.

Основные блоки:

- основная информация;
- изображения;
- категории;
- варианты;
- цена;
- складская связка;
- публикация;
- SEO позже.

Поля:

- название;
- slug;
- описание;
- статус;
- активность;
- категории;
- изображения;
- вариант: SKU, barcode, название, цена, валюта, вес, requires shipping, manage inventory, allow backorder.

Действия:

- сохранить товар;
- добавить вариант;
- удалить вариант позже;
- загрузить изображение;
- назначить категорию;
- опубликовать или скрыть;
- открыть остатки.

Данные:

- `products`;
- `product_variants`;
- `product_options`;
- `product_option_values`;
- `variant_option_values`;
- `product_images`;
- `categories`;
- `inventory_items`.

Состояния:

- новый товар;
- товар с одним вариантом;
- товар с несколькими вариантами;
- товар без SKU;
- товар без изображения;
- товар скрыт.

MVP:

- один вариант по умолчанию;
- несколько вариантов можно заложить в модель, но UI сделать простым;
- базовые изображения;
- базовая цена.

Позже:

- конструктор вариантов по опциям;
- SEO;
- bulk price update;
- channel-specific prices.

## Экран 6: Остатки

Цель: видеть наличие товаров и быстро исправлять количество.

Основные блоки:

- список остатков;
- фильтр по складу;
- фильтр по низкому остатку;
- ручная корректировка;
- резервы.

Колонки:

- товар;
- вариант;
- SKU;
- склад;
- доступно;
- зарезервировано;
- ожидается;
- обновлено.

Действия:

- изменить количество;
- открыть товар;
- посмотреть резервы;
- отфильтровать низкие остатки.

Данные:

- `inventory_items`;
- `inventory_levels`;
- `inventory_reservations`;
- `stock_locations`;
- `product_variants`;
- `products`.

Состояния:

- один склад по умолчанию;
- несколько складов позже;
- нет складского учета для варианта;
- есть резерв;
- количество ниже порога;
- отрицательное доступное количество запрещено без `allow_backorder`.

MVP:

- один склад;
- ручное изменение `stocked_quantity`;
- показ `reserved_quantity`;
- простой список низких остатков.

Позже:

- движения склада;
- incoming quantity;
- несколько складов;
- импорты остатков.

## Экран 7: Настройки магазина

Цель: управлять базовыми параметрами магазина без технической перегрузки.

Основные блоки:

- профиль магазина;
- домен;
- валюта и часовой пояс;
- контакты;
- пользователи и роли;
- способы оплаты;
- способы доставки;
- каналы продаж.

Поля:

- название магазина;
- slug;
- основной домен;
- валюта;
- часовой пояс;
- email/phone;
- активный sales channel.

Действия:

- сохранить профиль;
- перейти к техническому статусу домена;
- пригласить сотрудника;
- назначить роль;
- включить ручной способ оплаты;
- включить ручной способ доставки.

Данные:

- `stores`;
- `sales_channels`;
- `users`;
- `roles`;
- `user_roles`;
- `payments`;
- `deliveries`.

Состояния:

- домен не подключен;
- домен подключен, SSL не готов;
- нет сотрудников;
- ручная оплата включена;
- доставка не настроена.

MVP:

- профиль магазина;
- пользователи и роли;
- простые ручные оплаты/доставки;
- переход к техническому состоянию.

Позже:

- интеграции оплат;
- интеграции доставок;
- тариф и биллинг;
- несколько каналов продаж.

## Экран 8: Техническое состояние

Цель: показать владельцу, что managed hosting реально работает и контролируется.

Основные блоки:

- домен;
- SSL;
- backend healthcheck;
- database healthcheck;
- последние бэкапы;
- журнал действий;
- поддержка.

Действия:

- проверить статус;
- создать обращение в поддержку;
- запросить бэкап у оператора платформы;
- открыть журнал действий;
- перейти в настройки домена.

Данные:

- `stores`;
- `backups`;
- `audit_logs`;
- будущие healthcheck read models.

Состояния:

- все работает;
- домен не настроен;
- SSL ожидает выпуска;
- последний бэкап старый;
- backend недоступен;
- база недоступна;
- нет прав на технические действия.

MVP:

- отображать статус домена/SSL как поля магазина;
- показывать последние бэкапы;
- показывать журнал действий;
- давать кнопку поддержки.

Позже:

- автоматические healthchecks;
- ручной запуск бэкапа;
- восстановление;
- логи интеграций;
- статус Own Infra agent.

## Что это дает для разработки

Первый backend/UI поток можно строить так:

1. Tenant и Store.
2. User и Role.
3. Product и ProductVariant.
4. InventoryItem и InventoryLevel.
5. Cart и Order.
6. Admin screens: Сегодня, Заказы, Товары, Остатки.

Такой порядок дает видимый результат быстро: можно создать магазин, добавить товар, увидеть остаток, оформить заказ и обработать его в админке.
